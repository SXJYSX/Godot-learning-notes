📘 **Godot 4 攻击与受击架构笔记（Hitbox / Hurtbox 解耦与数值透传）**

### 📌 核心设计理念：攻击者驱动 + 基础类型数据透传

- **攻击者驱动**：碰撞监听代码写在 `Hitbox.gd`（攻击方）中，主动调用受击方的接收函数。
    
- **数据安全（值传递）**：只向受击方传递 `int` / `Vector2` / `float` 等**基础数据类型**，绝不传递 `Hitbox` 对象引用（`self`），从根源上杜绝数据被篡改。
    

### 🔄 完整数据流转

$$\text{Hitbox (检测碰撞)} \xrightarrow{\text{调用方法并传参}} \text{Hurtbox (透传数据)} \xrightarrow{\text{抛出信号}} \text{Player.gd (血量/物理结算)}$$

### 🛠️ 代码结构分工

#### 1. `Hitbox.gd`（攻击者：主动发起）

- **职责**：监听 `area_entered` 信号，检测到 `Hurtbox` 时，将自身伤害数值压给受击者。
    
- **核心代码**：
    
    GDScript
    
    ```
    func _on_area_entered(area: Area2D) -> void:
        if area is Hurtbox:
            area.receive_damage(damage, global_position, knockback_force)
    ```
    

#### 2. `Hurtbox.gd`（受击者：只做数据中转）

- **职责**：暴露接口供 `Hitbox` 调用，将收到的基础数值通过 `signal` 抛给父节点。
    
- **核心代码**：
    
    GDScript
    
    ```
    signal hit_received(damage: int, attacker_pos: Vector2, knockback: float)
    
    func receive_damage(damage: int, attacker_pos: Vector2, knockback: float) -> void:
        hit_received.emit(damage, attacker_pos, knockback)
    ```
    

#### 3. `Player.gd`（主逻辑：无敌门禁与状态结算）

- **职责**：监听 `Hurtbox` 信号，处理无敌帧拦截、扣血、击退与受击僵直。
    
- **核心代码**：
    
    GDScript
    
    ```
    func _on_take_damage(damage: int, attacker_pos: Vector2, knockback: float) -> void:
        if is_invincible:
            return
    
        hp -= damage
        apply_knockback(attacker_pos, knockback)
        start_invincibility()
    ```
    

### 💡 方案优势

- **数据绝对安全**：`Hurtbox` 无法拿到 `Hitbox` 对象引用，零篡改风险。
    
- **单向数据流**：数据只管往下/往上传递，逻辑清晰。
    
- **贴合 Unity 习惯**：本质上与 Unity 中使用 `OnTriggerEnter` 调用 `IDamageable.TakeDamage(damage, pos)` 的接口模式完全一致。
