## 一、状态划分

### 推荐的基本状态
```
Ground（地面）→ Jump（主动上升）→ Fall（下落）→ Ground
```

### 为什么 Jump 和 Fall 要分开？
- Jump：主动跳跃上升阶段，监听松开跳跃键的短跳逻辑
- Fall：下落阶段，处理土狼时间、二段跳、空中攻击
- 如果合并成一个"空中状态"，内部要用 `velocity.y < 0` 区分上升和下落，违背状态机"职责单一"的原则

### 跳跃逻辑应该由 Jump 状态自己负责
```gdscript
# ❌ 错误：每个状态都写一遍跳跃速度
# Ground状态：velocity.y = JUMP_VELOCITY
# Coyote状态：velocity.y = JUMP_VELOCITY

# ✅ 正确：任何状态只说"我要跳了"
transition_to(JumpState)
# Jump状态的on_enter负责"怎么跳"
func on_enter(params: Dictionary = {}):
    velocity.y = JUMP_VELOCITY
```

## 二、土狼时间（Coyote Time）

### 属于哪个状态？
属于 **Fall 状态**，在切换到 Fall 时通过参数传递是否启动土狼计时器。

```gdscript
# 从地面走下平台时
state_machine.transition_to(FallState, {"coyote_jump": true})

# 从Jump顶点自然下落时
state_machine.transition_to(FallState, {"coyote_jump": false})

# Fall状态的on_enter
func on_enter(params: Dictionary = {}):
    if params.get("coyote_jump", false):
        coyote_jump_timer.start()
```

### 土狼时间 vs 输入缓冲（对称设计）
| 机制 | 解决的问题 | 方向 |
|---|---|---|
| 土狼时间 | 刚离地还能跳 | 过去的状态宽容现在的输入 |
| 输入缓冲 | 提前按键还能跳 | 现在的输入宽容未来的状态 |

## 三、Coyote 状态

### 什么时候需要单独设立？
如果游戏足够复杂（比如地面攻击和空中攻击有明显差异），Coyote 状态值得单独存在：

```
地面状态：地面攻击 ✅  跳跃 ✅
Coyote状态：地面攻击 ❌（替换为空中普攻）  跳跃 ✅  上挑攻击 ✅
空中状态：空中攻击 ✅  二段跳 ✅
```

## 四、状态基类设计

```gdscript
# state.gd
class_name State

func on_enter(params: Dictionary = {}): pass   # 可选参数，默认空字典
func on_exit(): pass
func update(delta: float): pass
```

### 关于 on_enter 的参数设计
- `func on_enter(params: Dictionary = {})` → 可选参数，不传时默认为空字典
- `func on_enter(params: Dictionary)` → 必选参数，不传会报错
- GDScript 不支持方法重载，用默认参数代替

## 六、延迟切换（防止同帧多次切换）

```gdscript
# state_machine.gd
var pending_state = null
var pending_params = {}

func transition_to(new_state, params: Dictionary = {}):
    pending_state = new_state   # 只登记，不立即切换
    pending_params = params

func _physics_process(delta):
    current_state.update(delta)
    if pending_state:
        current_state.on_exit()
        current_state = pending_state
        current_state.on_enter(pending_params)
        pending_state = null
        pending_params = {}
```

## 七、输入缓冲（Input Buffer）

解决"操作被吞掉"的问题，将输入意图保留若干帧。

```gdscript
# input_buffer.gd
class_name InputBuffer

var _timers: Dictionary = {}
const BUFFER_TIME = 0.1

func tick(delta: float):
    for action in _timers:
        _timers[action] -= delta

func register(action: String):
    _timers[action] = BUFFER_TIME

func consume(action: String) -> bool:
    if _timers.get(action, 0.0) > 0.0:
        _timers[action] = 0.0
        return true
    return false
```

使用方式：
```gdscript
# _physics_process 里统一登记
input_buffer.tick(delta)
if Input.is_action_just_pressed("jump"):
    input_buffer.register("jump")
if Input.is_action_just_pressed("attack"):
    input_buffer.register("attack")

# 各状态结束时消费
if input_buffer.consume("jump"):
    transition_to(JumpState)
```

## 八、状态优先级

同一帧多个合法切换申请时，必须明确优先级顺序：

```gdscript
# 优先级从高到低
if is_on_wall() and input_buffer.consume("jump"):
    transition_to(WallJumpState)      # 最高：蹬墙跳
elif input_buffer.consume("jump") and can_jump():
    transition_to(JumpState)          # 其次：普通跳
elif is_on_wall():
    transition_to(WallSlideState)     # 再次：贴墙滑行
```

## 九、全局输入 vs 状态输入

| 层级 | 负责的输入 | 在哪里处理 |
|---|---|---|
| 全局层 | 大招、暂停、道具 | 状态机的`_physics_process` |
| 状态层 | 跳跃、攻击、移动 | 各个状态内部 |

```gdscript
# state_machine.gd
func _physics_process(delta):
    # 全局层：优先于所有状态
    if not current_state is DeadState:
        if input_buffer.consume("ultimate"):
            transition_to(UltimateState)
            return

    # 状态层
    current_state.update(delta)
```

### 用 is 判断状态类型
```gdscript
if not current_state is DeadState: pass   # GDScript
if (!(currentState is DeadState)) { }     // C# 对照
```

## 十、InputBuffer 和 InputHandler 的关系

两者可以合并成一个统一的输入管理模块：
- **InputHandler**：翻译原始输入，返回结构化数据
- **InputBuffer**：缓冲输入意图，防止操作被吞

合并后，状态机只需要和这一个模块打交道。
