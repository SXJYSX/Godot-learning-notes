### 总结选择口诀

1. **同场景复制节点产生联动？** $\rightarrow$ 右键 Shape 资源点击 **Make Unique**。
    
2. **代码会在运行时动态改 Shape 大小？** $\rightarrow$ 展开 Shape 资源勾选 **Local to Scene**。
    
3. **摆好后运行时绝对不动的静态碰撞盒？** $\rightarrow$ 保持默认，啥也不用勾。


你需要严格区分 **“使之唯一 (Make Unique)”** 与 **“仅本地场景 (Local to Scene)”** 的应用场景。你刚才遇到的“复制节点导致大小联动”问题，**90% 只需要用“使之唯一”解决，盲目全勾选 `Local to Scene` 属于内存浪费。**

### 1. 两者的核心区别

- **使之唯一 (Make Unique)**：**【编辑器解耦】** 解决“在同一个 `.tscn` 场景树里 `Ctrl+D` 复制了 `PlayerHurtbox` 得到 `TriggerReceiver`，导致两者 Shape 联动”的问题。**点一次即断开连接**。
    
- **仅本地场景 (Local to Scene)**：**【运行时实例解耦】** 解决“游戏运行后，如果实例化了 2 个 Player（双人同屏），Player 1 在代码里用 GDScript 动态修改了 Shape 大小，导致 Player 2 的 Shape 也跟着变”的问题。
    

### 2. 逐节点配置建议

针对你当前场景树中的 `Sensors` 子节点：

**需要勾选 `Local to Scene` 的节点（按需勾选）：**

- **`PlayerHurtbox` / `PhysicsCollision`**：**（建议勾选）**
    
    - **原因**：如果你的游戏有“下蹲、滑铲、变身”机制，需要**在 GDScript 代码里动态缩放/修改 Shape 尺寸**。勾选它能保证多玩家或多实体时，代码修改只作用于当前玩家本体。
        

**只需要做一次“Make Unique”，无需勾选 `Local to Scene` 的节点：**

- **`TriggerReceiver` / `EnvironmentDetector` / `FootTarget`**
    
    - **原因**：这些节点的碰撞盒大小通常在编辑器里**拖好就固定不变**，运行时不会写代码去改它们的大小。它们共享静态 Resource 可以节省内存。当初复制产生联动，只需要在 Inspector 里点一次 **“Make Unique”** 即可。
        

**完全不需要管的节点：**

- **`InteractableCast` / `WallCast` (RayCast2D)**
    
    - **原因**：`RayCast2D` 没有 Shape 资源，它的方向和长度是节点的 `target_position` 属性，复制时天然独立，完全不存在共享 Resource 的问题。
        
- **`FootDetector` (ShapeCast2D)**
    
    - 如果只用 ShapeCast2D 默认的形状，且运行时不改动，正常指定 Shape 即可。

---
在 GDScript 中动态修改 `CollisionShape2D` 时，通常会遇到两个致命隐患：

1. **资源共享污染**：直接改 `shape.size` 会导致其他使用同款 Shape 的敌人/角色同步变大变小。
    
2. **物理帧锁死（Physics Server Locked）**：在碰撞信号回调中直接切换 `disabled`，会导致引擎抛出报错或无效化。
    

**一、 彻底避免资源共享污染：`duplicate()` 最佳实践**

在代码中修改尺寸前，必须确保该 `Shape` 资源已独立。如果没在编辑器中勾选 `Local to Scene`，可通过代码在 `_ready()` 中深拷贝：

GDScript

```
# Player.gd
@onready var physics_collision: CollisionShape2D = %PhysicsCollision

func _ready() -> void:
	# 确保当前实例的 Shape 资源完全独立，防止改动污染全局预制体
	if physics_collision.shape:
		physics_collision.shape = physics_collision.shape.duplicate()

## 下蹲/恢复站立的尺寸切换示例
func set_crouch_shape(is_crouching: bool) -> void:
	var rect_shape := physics_collision.shape as RectangleShape2D
	if not rect_shape:
		return
		
	# 安全修改独置后的资源参数（假设站立高 32px，下蹲高 16px）
	var target_height: float = 16.0 if is_crouching else 32.0
	rect_shape.size.y = target_height
	
	# 调整 CollisionShape2D 相对位置，确保碰撞盒底部始终贴合脚底
	physics_collision.position.y = (32.0 - target_height) * 0.5
```

**二、 避免物理 Server 锁死：`set_deferred()` 最佳实践**

在信号回调（如 `_on_area_entered`）中**严禁直接赋值 `collision_shape.disabled = true`**。因为此时物理引擎正在进行碰撞遍历，直接关闭物理体极易引发未定义行为。

必须使用 `set_deferred()` 将物理修改推迟到当前物理帧末尾执行：

GDScript

```
# PlayerHurtbox.gd
@onready var shape_node: CollisionShape2D = $CollisionShape2D

## 开启/关闭无敌帧或伤害接收
func set_invincible_deferred(is_invincible: bool) -> void:
	# ❌ 错误写法：在碰撞回调中直接改属性
	# shape_node.disabled = is_invincible
	
	# ✅ 正确写法：通知 PhysicsServer 在本次物理刷新的安全时刻执行修改
	shape_node.set_deferred("disabled", is_invincible)

## 同理，如果在碰撞帧内需要临时改变 Shape 形状/层级，也建议延迟设置
func disable_hitbox_safely() -> void:
	set_deferred("monitoring", false)
```

**总结口诀与规避避坑准则**

- **修改 `shape.size` / `radius`** $\rightarrow$ 先执行 `shape = shape.duplicate()`，直接写 `rect_shape.size.y = val`（无需 deferred）。
    
- **修改 `disabled` / `monitoring` / `monitorable`** $\rightarrow$ 只要发生在信号回调或物理帧逻辑里，**强制使用 `set_deferred("属性名", 值)`**。
