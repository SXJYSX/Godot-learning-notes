哦，我们成功把毒教程的敌人AI伪状态机 拆分成了如下部分，按照调用顺序，排列如下：

1、Goblin，这是顶级父节点，控制各个子节点的执行顺序；

只有它有_process_physics方法，依次调用子节点



2_1、GoblinBrain，这是执行策略节点，根据 1 3 4 的数据 和自身的算法逻辑，切换行为模式

2_2、IdleMode、PatrolMode，这些是具体的行为模式，只负责模拟手柄和动作指令，不负责切换行为模式。

这俩之所以都是2开头，是因为它们在节点上是父子关系，在代码上是所属关系。

  

3_1、StateMachine 动作类节点们的管理器，敌人和玩家都是类似的

3_2、IdleState、MoveState 具体的动作。

  

4_1、Sensors，各种传感器，在Goblin刚出生 和 每个物理帧最后的时候 刷新检测。

4_2、具体的某传感器，有自己的自定义脚本，有公开的检测结果可以被访问。 

-----------

结合“动作意图裁决”**（前置，解决输入/状态竞争）和**“环境结果裁决”（后置，解决物理碰撞/标记收尾），完善后的单物理帧完整流水线如下：

Plaintext

```
[ 帧开始 ]
   │
   ├── 1. 【1 Goblin 根节点】_physics_process(delta) 触发，掌控全局调度
   │
   ├── 2. 【2_1 GoblinBrain】大脑决策与意图生成
   │      ├── 读取【4_1 Sensors】上一帧留下的环境数据与【3_1 StateMachine】的状态
   │      ├── 评估并决议是否切换行为模式（如 PatrolMode -> ChaseMode）
   │      └── 驱动【2_2 当前 Mode】生成本帧的“虚拟手柄意图 (AIIntent)”并更新输入缓冲
   │
   ├── 3. 【3_1 StateMachine】动作计算与 ⚡【动作意图裁决】（发生在物理移动前）
   │      ├── 当前【3_2 State】根据 AIIntent 计算速度，并向优先级池抛出切换申请
   │      ├── ⚡【动作意图裁决】（Action Arbitration）：
   │      │     ├─ 汇总当帧所有申请（如“攻击自然收招” vs “跳跃预输入”）
   │      │     └─ 按 priority 从大到小排序，最高优先级 State 胜出并立即 enter()
   │      └── 胜出的 State 赋予 actor.velocity 最新物理速度，做到当帧起飞/移动零延迟！
   │
   ├── 4. 【1 Goblin 根节点】执行物理位移
   │      └── 调用 move_and_slide()，物理引擎根据当帧最新 velocity 完成位移与碰撞响应
   │
   └── 5. 【4_1 Sensors】刷新检测与 ⚡【环境结果裁决】（Late Physics Update，发生在物理移动后）
          ├── 🔍 刷新检测（Sensors Refresh）：
          │     └─ 基于当帧位移后的全新坐标，刷新射线/区域传感器，获取最新的 is_on_floor() / is_on_wall() 物理事实
          └── ⚡【环境结果裁决】（Environmental Arbitration）：
                ├─ 根据最新物理事实做强制裁决（如撞墙强制中断冲刺、撞天花板清空 y 轴速度、落地重置二段跳）
                └─ 清理当帧一次性标记（如 consume_hit_flag()），将干净纯粹的数据留给下一帧的大脑
   │
[ 帧结束 ]
```

### 两种裁决的核心差异对比

| **裁决维度**   | **⚡ 1. 动作意图裁决 (Action Arbitration)**                            | **⚡ 2. 环境结果裁决 (Environmental Arbitration)**            |
| ---------- | --------------------------------------------------------------- | ------------------------------------------------------ |
| **发生时机**   | **`move_and_slide()` 之前**                                       | **`move_and_slide()` 之后** _(Late Physics Update)_      |
| **解决的痛点**  | 避免预输入被“吞按键”、解决同一帧内多个状态切换申请的抢占竞争。                                | 避免依据旧坐标做物理判断导致的“延迟一帧生效”或“错判”Bug。                       |
| **裁决依据**   | 玩家按键缓冲（Buffer） + 各 State 报上来的优先级数值（Priority）。                   | 刚执行完 `move_and_slide()` 得到的绝对真实物理事实（如 `is_on_wall()`）。 |
| **典型裁决行为** | 从 `[Idle(0), Jump(100)]` 中选择 `JumpState`，**立即赋予 `velocity.y`**。 | 检测到已撞墙，强行把 `velocity.x` 裁决归零并打断冲刺；清空单帧受击标记。            |

这套流水线在 `move_and_slide()` **前**搞定“想做什么”（动作零延迟），在 `move_and_slide()` **后**搞定“发生了什么”（物理绝对真实），从逻辑上彻底关死了所有吞按键、帧序错乱和物理穿模的漏洞！
