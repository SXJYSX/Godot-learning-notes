教程里的写法能够工作，原理是利用了 **`queue_free()` 延迟删除** 的特性：调用 `queue_free()` 时节点不会立刻被销毁，而是在当前帧末尾才从场景树移除。因此执行 `get_nodes_in_group()` 时，自身还在列表中，`size() == 1` 刚好意味着“我就是全场最后一个”。

但这属于典型的 **“教学原型写法”**，在正规项目架构中存在严重隐患：

1. **违背单一职责原则（SRP）**：一个小小的 `Heart` 道具不应该知道也不应该关心“关卡是否通关”这种全局大逻辑。
    
2. **缺乏 UI 支持**：如果游戏界面要显示“已收集：3/5”，这种写法很难把数据推给 UI。
    
3. **逻辑散乱**：未来如果通关要播放音效、显示结算面板、锁定玩家操作，全写在 `heart.gd` 里会导致代码极难维护。
    

### 更好的架构设计：关卡/系统管理者（Level Manager）统一计数

把逻辑解耦为：**道具只负责“告知自己被捡了”，关卡/系统负责“统计与判定通关”。**

#### 1. 道具侧（`heart.gd`）

保持绝对纯粹，通知外部后直接销毁，不处理任何游戏流程。

GDScript

```
class_name Heart
extends Node2D

# 向上抛出信号（也可以使用全局 EventBus）
signal collected

@onready var item_receiver: ItemReceiver = %ItemReceiver

func _ready() -> void:
	item_receiver.item_touched.connect(_on_item_receiver_touched)

func _on_item_receiver_touched() -> void:
	collected.emit() # 广播“我被拾取了”
	queue_free()
```

#### 2. 关卡侧（`level.gd` 或 `level_manager.gd`）

在关卡初始化时统一注册并维护计数器。

GDScript

```
class_name Level
extends Node2D

var total_hearts: int = 0
var collected_hearts: int = 0

func _ready() -> void:
	# 1. 初始化时一次性获取所有心，避免每捡一个就 get_nodes_in_group 一次
	var hearts = get_tree().get_nodes_in_group("Hearts")
	total_hearts = hearts.size()
	
	# 2. 批量监听所有心的拾取信号
	for heart in hearts:
		if heart is Heart:
			heart.collected.connect(_on_heart_collected)

func _on_heart_collected() -> void:
	collected_hearts += 1
	
	# 3. 顺便更新 UI 界面（如：3 / 5）
	# UIManager.update_heart_count(collected_hearts, total_hearts)
	
	# 4. 统一判定通关
	if collected_hearts >= total_hearts:
		_complete_level()

func _complete_level() -> void:
	print("Level Completed!")
	# 触发通关动画、禁止玩家输入、打开结算菜单等...
```

### 两种设计对比

|维度|教程写法（Heart 自行判定）|架构化写法（Level 统一管理）|
|---|---|---|
|**性能**|每次拾取都重新查找场景树节点列表|仅在 `_ready` 查找一次，之后靠数字自增|
|**UI 联动**|极难扩展“已收集/总数”UI 计数|天然支持 UI 更新|
|**流程控制**|关卡结算逻辑写在道具脚本里，高度耦合|结算逻辑全在 Level/GameManager，清晰集中|
|**健壮性**|依赖 `queue_free()` 帧末删除的时序隐患|纯数值增量比较，绝对可靠|

那你觉得levelmanager应该是 level_01的子节点，还是作为一个全局单例节点？

最推荐的做法是采用 **“两层分工架构”**：**不要把 `LevelManager` 做成直接管关卡内节点的 Autoload 单例，也不要把全局逻辑塞进单独的 `level_01` 子节点中**。

### 最佳架构分工：局部 Level + 全局 SceneManager

|角色|挂载位置|核心职责|能否按 F6 独立测试关卡|
|---|---|---|---|
|**`Level` (关卡控制器)**|`level_01.tscn` 的 **根节点** (`level.gd`)|**关卡局部逻辑**：统计本关爱心数量、监听本关爱心拾取、刷新本关 UI|**✅ 可以**（随时按 F6 独立运行测试 `level_01.tscn`）|
|**`SceneManager` (全局管理器)**|**Autoload (全局单例)**|**跨关卡全局逻辑**：切换场景/加载关卡、跨关卡数据持久化（金币/生命值）、全局淡入淡出动画|**✅ 不受影响**（作为单例后台静默运行）|

### 为什么不能把“关卡内计数”直接交给全局 Autoload 单例？

1. **破坏 Godot 的 F6 独立测试工作流**： 如果全局单例需要去抓取 `level_01` 里的爱心，当你直接在编辑器里按下 **F6** 单独测试 `level_02.tscn` 时，单例代码很可能会因为找不到节点而直接崩溃抛错。
    
2. **野指针与内存泄漏隐患**： 全局单例的生命周期贯穿整个游戏。如果单例里保存了 `level_01` 中某些节点的引用，切关销毁场景时容易产生悬空指针（Dangling Pointer）或节点无法释放的问题。
    

### 标准工作流链路（极度解耦）

Plaintext

```
[Heart.gd] (爱心节点)
   └── 拾取后发出信号: collected.emit()
         │
         ▼
[Level.gd] (level_01.tscn 根节点)
   └── 监听 local 爱心信号，进行内部计数 (3/3)
   └── 满足通关条件后，通知全局单例: SceneManager.change_level("res://levels/level_02.tscn")
         │
         ▼
[SceneManager] (Autoload 全局单例)
   └── 播放关卡过渡遮罩动画
   └── 执行 get_tree().change_scene_to_file(...) 切换关卡
```

#### 1. 关卡根节点脚本 (`level.gd`)

直接挂在 `level_01.tscn` 的最顶层节点上：

GDScript

```
class_name Level
extends Node2D

# 错误代码：会导致严重的内存隐患和架构危机
 @export var next_level_scene: PackedScene  # Godot 底层的 PackedScene 强引用机制：只要你在一个场景的 @export 属性里拖入了一个 .tscn，
                                            # Godot 在加载当前场景时，就会同步将引用的 PackedScene 预加载到内存中。

var total_hearts: int = 0
var collected_hearts: int = 0

func _ready() -> void:
	var hearts = get_tree().get_nodes_in_group("Hearts")
	total_hearts = hearts.size()
	
	for heart in hearts:
		if heart is Heart:
			heart.collected.connect(_on_heart_collected)

func _on_heart_collected() -> void:
	collected_hearts += 1
	if collected_hearts >= total_hearts:
		_on_level_completed()

func _on_level_completed() -> void:
	# 局部逻辑处理完毕后，通知全局单例切关
	if next_level_scene:
		SceneManager.change_scene(next_level_scene)
```

#### 2. 全局单例脚本 (`scene_manager.gd` / Autoload)

仅负责跨场景的切换与淡入淡出等全局服务：

GDScript

```
# scene_manager.gd (配置在 Project Settings -> Autoload 中)
extends Node

func change_scene(target_scene: PackedScene) -> void:
	# 这里可以播放全局黑屏过渡动画
	get_tree().change_scene_to_packed(target_scene)
```
