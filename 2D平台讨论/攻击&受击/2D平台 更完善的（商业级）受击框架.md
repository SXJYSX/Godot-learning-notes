当引入 **“玩家攻击敌人”**、**“多种 Hitbox 碰撞后行为”** 以及 **“多种受击主体（玩家/敌人/木箱）”** 后，整个攻击受击系统就从“一对一”升级为了“多对多”的通用战斗框架。

要优雅地容纳这些复杂情况，我们需要在原有架构的基础上，做三项核心升级：**碰撞层阵营隔离**、**Hitbox 命中后的生命周期 Hook（钩子）**，以及 **统一的数据包（`HitData`）**。

### 1. 第一层：碰撞层阵营隔离（Layer & Mask）

无论是玩家打敌人，还是敌人打玩家，逻辑代码完全可以共享同一套，**唯一的区别在于 Collision Layer 和 Mask 的设置**：

| **实体分类**             | **Collision Layer（我是什么）** | **Collision Mask（我检测谁）** | **结果**           |
| -------------------- | ------------------------- | ------------------------ | ---------------- |
| **玩家 Hurtbox**       | Layer 2 (`PlayerHurtbox`) | _None_                   | 被动等待被撞           |
| **敌人 Hurtbox**       | Layer 3 (`EnemyHurtbox`)  | _None_                   | 被动等待被撞           |
| **玩家 Hitbox**（武器/子弹） | Layer 4 (`PlayerHitbox`)  | Mask 3 (`EnemyHurtbox`)  | **只检测敌人，绝不误伤玩家** |
| **敌人 Hitbox**（爪子/弹幕） | Layer 5 (`EnemyHitbox`)   | Mask 2 (`PlayerHurtbox`) | **只检测玩家，绝不误伤敌人** |
| **环境陷阱 Hitbox**（尖刺）  | Layer 6 (`EnvHitbox`)     | Mask 2 + Mask 3          | **玩家和敌人踩上去都会受击** |

### 2. 第二层：统一传递的数据载体（`HitData`）

为了应对复杂战斗（如火元素伤害、爆头双倍、暴击、击退方向），我们不再传递孤立的 `damage` 或 `position`，而是使用一个标准的载体结构。

在 Godot 4 中，推荐定义一个轻量的自定义类：

GDScript

```
# hit_data.gd
class_name HitData
extends RefCounted  # 自动内存管理的轻量级数据对象

var damage: int = 10
var knockback_force: float = 100.0
var attacker_position: Vector2 = Vector2.ZERO
var is_critical: bool = false
var element_type: String = "PHYSICAL" # 例如: FIRE, ICE, PHYSICAL

func _init(p_damage: int, p_knockback: float, p_pos: Vector2) -> void:
	damage = p_damage
	knockback_force = p_knockback
	attacker_position = p_pos
```

### 3. 第三层：Hitbox 命中后的多态行为（子弹/挥刀/手雷）

针对你提到的三种 Hitbox 类型（消失、留存、爆炸），我们无需写三套独立的 Hitbox，而是**在基类 `Hitbox.gd` 中留出回调接口（Hook），由具体物体去重写**：

#### 基础 `Hitbox.gd`（通配基类）

GDScript

```
# hitbox.gd
class_name Hitbox
extends Area2D

@export var damage: int = 10
@export var knockback_force: float = 100.0

# 命中成功时发出的信号
signal hit_delivered(target_hurtbox: Hurtbox)

func _ready() -> void:
	area_entered.connect(_on_area_entered)

func _on_area_entered(area: Area2D) -> void:
	if area is Hurtbox:
		var hit_data = HitData.new(damage, knockback_force, global_position)
		
		# 尝试向 Hurtbox 发送伤害，Hurtbox 会返回是否成功（例如对方是否处于无敌状态）
		var is_accepted = area.receive_hit(hit_data)
		
		if is_accepted:
			hit_delivered.emit(area)
			_on_hit_success(area) # 虚函数 Hook：交给子类实现后续行为

# 虚函数：默认什么都不做（挥刀等持续存在的 Hitbox 保持默认即可）
func _on_hit_success(_target: Hurtbox) -> void:
	pass
```

#### 情况 A：子弹（造成伤害后自身销毁）

只针对子弹，重写 `_on_hit_success` 即可：

GDScript

```
# bullet_hitbox.gd
extends Hitbox

func _on_hit_success(_target: Hurtbox) -> void:
	# 命中敌人后，销毁整个子弹节点（也可以播放击中粒子特效）
	owner.queue_free() 
```

#### 情况 B：手雷（造成伤害后触发爆炸）

手雷命中目标后，在原地点燃一个范围爆炸（生成一个新的爆炸 Hitbox），然后销毁自身：

GDScript

```
# grenade_hitbox.gd
extends Hitbox

@export var explosion_scene: PackedScene

func _on_hit_success(_target: Hurtbox) -> void:
	# 1. 在当前位置生成范围爆炸（爆炸本身可以是一个大型持久 Hitbox）
	if explosion_scene:
		var explosion = explosion_scene.instantiate()
		explosion.global_position = global_position
		get_tree().current_scene.add_child(explosion)
		
	# 2. 销毁手雷实体
	owner.queue_free()
```

#### 情况 C：近战挥刀 / 持续判定（自身留存）

基类默认行为就是留存，无需额外写代码。如果希望一次挥刀只对每个敌人造成一次伤害，只需在刀光生成时维护一个已击中列表（`hit_targets`），防止一帧内多次判定即可。

### 4. 第四层：Hurtbox 的统一性与受击主体的响应差异

`Hurtbox.gd` 的代码对于**玩家、敌人、甚至可破坏木箱**来说，是 **100% 完全相同**的：

GDScript

```
# hurtbox.gd
class_name Hurtbox
extends Area2D

signal hit_received(hit_data: HitData)

# 供外部 Hitbox 调用，返回 bool 告知对方“我是否真的受到了伤害”
func receive_hit(hit_data: HitData) -> bool:
	# 如果处于无敌状态或已死亡，拒绝接伤
	if not monitoring or not is_active:
		return false
		
	hit_received.emit(hit_data)
	return true
```

#### 不同受击主体的分工差异：

当 `Hurtbox` 把 `hit_data` 抛出后，不同的父节点根据自身需求做完全不同的业务结算：

```
                    ┌───► Player.gd   ──► 触发无敌帧 / 减血 / 广播至 UI / 播放受击音效
                    │
HitData ──► Hurtbox ┼───► Enemy.gd    ──► 减血 / 弹出伤害数字 / 削减韧性值(Stagger) / 切入受击硬直 State
                    │
                    └───► WoodCrate.gd ─► 扣除木箱耐久 / 产生木屑粒子 / 掉落金币
```

1. **玩家（`Player.gd`）**：
    
    - 触发 **无敌帧（I-Frames）**，暂时关闭 `Hurtbox` 的监测。
        
    - 发送 `Events.player_health_changed` 信号给全局 UI 刷新血条。
        
    - 状态机切入 `HurtState`（控制播放受击动画和玩家打断）。
        
2. **敌人（`Enemy.gd`）**：
    
    - **没有无敌帧（或者只有极短的硬直受击保护）**。
        
    - 在头顶生成一个 **飘字数字（Damage Number）** 组件。
        
    - 计算 **韧性/削韧（Poise/Stagger）**：当累计伤害或击退力达到阈值，才打断当前敌人攻击并切入 `StaggerState`，否则只闪红不硬直。
        
3. **可破坏道具（`WoodCrate.gd`）**：
    
    - 不需要状态机，直接扣除 `HP`。
        
    - `HP <= 0` 时，调用 `spawn_loot()` 爆金币并销毁节点。
        

### 📊 完整系统架构全景速查

|**模块**|**职责**|**对外暴露出什么**|**是否包含逻辑业务**|
|---|---|---|---|
|**`HitData`**|纯粹的数据容器|属性：`damage`, `knockback`, `element`|❌ 无逻辑，仅存储|
|**`Hitbox`**|监听重叠，尝试向对方“塞”数据，并处理自身消亡|信号：`hit_delivered`<br><br>  <br><br>Hook：`_on_hit_success()`|⚠️ 仅包含 Hitbox 自身的销毁/爆炸逻辑|
|**`Hurtbox`**|接口管道，接收数据并往上抛|信号：`hit_received`<br><br>  <br><br>方法：`receive_hit(hit_data)`|❌ 无业务逻辑，只做门禁与中转|
|**`Player / Enemy / Crate`**|具体的受击响应者|各自的血量、硬直状态、音效、粒子、UI 响应|✅ 包含所有核心战斗机制与数值结算|

这套设计将物理检测（Hitbox/Hurtbox）、数据结构（HitData）、多态行为（消失/爆炸）、阵营判断（Layer/Mask）与游戏逻辑（Player/Enemy）**彻底解耦**。无论未来你的游戏增加多少种武器、怪物或道具，这套框架都无需推翻重构！
